Vier Bausteine jeder Befehlszeile

Stell dir eine Kellnerin mit Bestellzettel vor: Sie schreibt auf, was passieren soll (das Cmdlet) und wie genau (die Parameter). Die Küche liefert keine Beschreibung, sondern echte Teller (Objekte).

CmdletGet-ChildItem

Ein Befehl der Form Verb-Nomen. Das Verb sagt, was passiert.

Parameter-Path Logs

Beginnt mit einem Strich und präzisiert den Befehl.

Pipeline|

Reicht die Objekte an den nächsten Befehl weiter.

Objekt$_.Length

Ein Ergebnis mit Eigenschaften, zum Beispiel Name und Grösse.

Kurz üben: Cmdlet oder Parameter?

Schritt 1 · Befehle lesen

Ein Befehl und seine Ausgabe

Codeblöcke färbt ps-konsole.js beim Laden selbst ein: Cmdlets, Parameter, Variablen, Texte und Zahlen haben je eine Farbe. Kurze Befehle im Text schreibst du als Get-Date -Format 'dd.MM.yyyy'.

# Die drei grössten Logdateien
Get-ChildItem -Path Logs -Filter *.log |
  Sort-Object -Property Length -Descending |
  Select-Object -First 3 Name, @{ Name = 'MB'; Expression = { [math]::Round($_.Length / 1MB, 1) } }

Die Ausgabe darunter erzeugt der Simulator beim Laden selbst (data-ps-befehl). So stimmt sie immer mit dem Spiel-Rechner überein.


    
Ein Ausgabeblock darf auch von Hand geschrieben sein, zum Beispiel für eine Fehlermeldung. Fremdsprachiges gehört in lang="en".

    
PS C:\Users\lea> Get-ChildItem Protokolle
Get-ChildItem: Cannot find path 'C:\Users\lea\Protokolle' because it does not exist.

    
Merke: Die rote Meldung heisst: «Den Pfad gibt es nicht.» Prüfe die Schreibweise oder wo du gerade bist (Get-Location).

    
Unterschied 5.1: In Windows PowerShell 5.1 braucht Export-Csv zusätzlich -NoTypeInformation, sonst steht eine Typzeile in der Datei. In 7 ist das der Standard.

    
Falle: Import-Csv liefert alle Werte als Text. Where-Object Pensum -lt 100 vergleicht dann Texte («80» ist grösser als «100»).
