PS · Teil 2 · Dateisystem

Dateien und Ordner verwalten

Leas Downloads-Ordner ist ein Durcheinander: Rechnungen, Fotos und alte Installationsdateien liegen bunt gemischt. In dieser Station legst du Ordner und Dateien an, kopierst, verschiebst, benennst um und löschst, mit einem Sicherheitsnetz, das dich vor bösen Überraschungen schützt. Danach liest und schreibst du den Inhalt von Textdateien.

Lernziele

  • Du legst Ordner und Dateien mit New-Item an.
  • Du kopierst, verschiebst und benennst um mit Copy-Item, Move-Item und Rename-Item und weisst, wann du -Recurse brauchst.
  • Du löschst mit Remove-Item und prüfst vorher mit -WhatIf oder -Confirm.
  • Du liest Dateien mit Get-Content und unterscheidest Set-Content, Add-Content, Out-File, > und >>.
  • Du kennst den Unterschied beim Encoding zwischen PowerShell 7 und Windows PowerShell 5.1.

Schritt 0 · Ohne Vorwissen

Ein Aktenschrank, fünf Handgriffe

Stell dir einen Aktenschrank im Gemeindehaus vor. Darin hängen Mappen (Ordner), in den Mappen liegen Blätter (Dateien). Mit einer Mappe oder einem Blatt kannst du fünf Dinge tun: neu anlegen, kopieren, an einen anderen Ort legen, neu beschriften und wegwerfen. Für jeden Handgriff gibt es ein Cmdlet. Alle enden auf -Item, englisch für «Element». Ein Element ist eine Datei oder ein Ordner.

Ein Unterschied zum echten Büro ist wichtig: PowerShell hat keinen Papierkorb. Was Remove-Item löscht, ist weg. Darum gibt es eine Probefahrt: -WhatIf zeigt dir, was passieren würde, und tut nichts.

Element (Item)Dokumente\notizen.txt

Eine Datei oder ein Ordner. Wie ein Blatt oder eine Mappe im Aktenschrank.

Ziel (Destination)Dokumente\Archiv

Wohin du kopierst oder verschiebst. Gibt es den Zielordner nicht, entsteht etwas anderes als gedacht.

Mit Inhalt (-Recurse)-Recurse

«Samt allem, was drin ist». Ohne diesen Schalter nimmt PowerShell bei Ordnern nur die leere Mappe.

Probefahrt (-WhatIf)-WhatIf

Zeigt, was der Befehl tun würde, und tut nichts. Dein Sicherheitsnetz vor jedem Löschen.

Inhalt (Content)Get-Content

Der Text in einer Datei, Zeile für Zeile. Wie das, was auf dem Blatt steht.

Kurz üben: Welcher Handgriff passt?

Schritt 1 · Das Muster für jedes Löschen

Erst schauen, dann proben, dann löschen

Bevor du die einzelnen Cmdlets kennenlernst, siehst du das wichtigste Muster dieser Station. Lea braucht die beiden Word-Dateien im Ordner Dokumente nicht mehr. Klick dich mit «Weiter» durch. Fahre über ein unterstrichenes Satzstück: Der passende Teil des Befehls leuchtet auf.

Merke: Schauen mit Get-ChildItem, proben mit -WhatIf, erst dann löschen. Den Befehl für das echte Löschen holst du mit ↑ zurück und entfernst nur -WhatIf. So löschst du genau das, was du geprüft hast.
Schritt 2 · New-Item

Ordner und Dateien anlegen

Einen Ordner anlegen

New-Item legt ein neues Element an. Der Parameter -ItemType sagt, was es sein soll: Directory für einen Ordner, File für eine Datei. Lea legt im Ordner Dokumente einen Ordner für das Wolkenrieder Dorffest an.

New-Item -Path Dokumente\Fest -ItemType Directory

      
PowerShell zeigt das neue Element gleich an. Das d in der Spalte Mode steht für directory, also Ordner. Kürzer geht es mit mkdir Dokumente\Fest: mkdir ist eine eingebaute Abkürzung für genau diesen Befehl.

    

    

      
Eine Datei mit Text anlegen

      
Mit -ItemType File entsteht eine Datei. -Value schreibt gleich einen Text hinein. Ohne -Value ist die Datei leer (Length 0).

      
New-Item -Path Dokumente\Fest\helfer.txt -ItemType File -Value 'Helferliste Dorffest'

      

      
Die Datei ist 20 Bytes gross: 20 Buchstaben und Leerzeichen, sonst nichts. Merk dir das «sonst nichts», es wird bei den typischen Fehlern wichtig.

    

    

      
Gibt es das schon?

      
Existiert das Element bereits, legt New-Item nichts an und meldet einen Fehler. Das schützt dich davor, eine Datei aus Versehen zu ersetzen.

      

      
Auf Deutsch: «Ein Element mit diesem Namen gibt es schon.» Bei einer Datei lautet die Meldung The file '…' already exists. Der Schalter -Force würde eine bestehende Datei überschreiben. Nimm ihn nur, wenn du das wirklich willst.

    

  


  
  

    Schritt 3 · Copy-Item, Move-Item, Rename-Item
    
Kopieren, verschieben, umbenennen

    

      
Eine Datei kopieren

      
Copy-Item braucht zwei Angaben: was du kopierst (-Path, an erster Stelle) und wohin (-Destination, an zweiter Stelle). Die Parameternamen darfst du weglassen, wenn die Reihenfolge stimmt.

      
Copy-Item Dokumente\notizen.txt Dokumente\notizen-sicherung.txt
Get-ChildItem Dokumente -Filter notizen*

      

      

      
Copy-Item meldet nichts, wenn es klappt. Die Kopie behält Grösse und Änderungsdatum des Originals.

    

    

      
Einen Ordner kopieren: -Recurse nicht vergessen

      
Lea will den ganzen Ordner Dokumente sichern. Ohne -Recurse kopiert PowerShell nur die leere Mappe, nicht ihren Inhalt:

      

      

      
Keine Fehlermeldung, aber der Ordner Dokumente-Kopie ist leer. Mit -Recurse kommt alles mit, auch der Unterordner Archiv. -Name zeigt nur die Namen, mit Unterordner davor:

      

      

      
Tipp: Gibt es den Zielordner schon, legt Copy-Item -Recurse den Ordner darin an. Ein zweites Copy-Item Dokumente Dokumente-Sicherung -Recurse ergibt also Dokumente-Sicherung\Dokumente.

    

    

      
Verschieben

      
Move-Item funktioniert wie Copy-Item, nur bleibt am alten Ort nichts zurück. Ist das Ziel ein bestehender Ordner, landet die Datei darin. Ordner verschiebt Move-Item immer mit Inhalt, ein -Recurse braucht es nicht.

      
Move-Item Dokumente\bewerbung-alt.docx Dokumente\Archiv
Get-ChildItem Dokumente\Archiv

      

      

      
Gibst du als Ziel einen neuen Dateinamen an, verschiebt und benennt Move-Item in einem Zug:

      

      

      
Achtung: Gibt es den Zielordner nicht, hält PowerShell den Namen für einen neuen Dateinamen. Move-Item Downloads\foto-apero.jpg Fotos erzeugt dann eine Datei namens Fotos ohne Endung, keinen Ordner. Leg den Ordner immer zuerst an.

    

    

      
Umbenennen

      
Rename-Item gibt einem Element einen neuen Namen und lässt es, wo es ist. Der neue Name (-NewName, an zweiter Stelle) ist nur ein Name, kein Pfad.

      

      

      
Mit einem Pfad im neuen Namen weigert sich Rename-Item:

      

      
Auf Deutsch: «Das Ziel ist ein Pfad, damit kann ich nicht umbenennen.» Zum Verschieben nimmst du Move-Item.

    

  


  
  

    Schritt 4 · Remove-Item mit Sicherheitsnetz
    
Löschen, ohne es zu bereuen

    
Remove-Item löscht Dateien und Ordner endgültig. Es gibt keinen Papierkorb und kein «Rückgängig». Zwei Sicherheitsparameter helfen dir (die meisten Cmdlets, die etwas verändern, bieten sie an): -WhatIf und -Confirm.

    

      
-WhatIf: die Probefahrt

      
Mit -WhatIf schreibt PowerShell für jedes Element eine Zeile «What if: …» (was wäre, wenn) und löscht nichts. Platzhalter wie * kennst du aus Station 04.

      

      
Auf Deutsch: «Was wäre, wenn: Ich würde die Datei setup-alt.exe löschen.» Und genauso für die zweite Datei. Danach sind beide noch da.

    

    

      
-Confirm: einzeln nachfragen

      
-Confirm fragt vor jedem Element nach. Y (Yes) löscht dieses Element, A (Yes to All) alle weiteren, N (No) überspringt es, L (No to All) überspringt alle. Hier hat Lea N getippt:

      

      
Auf Deutsch: «Bist du sicher? Ich würde die Datei setup-alt.exe löschen.» Nach N bleibt die Datei liegen.

    

    

      
Ordner mit Inhalt: -Recurse

      
Löschst du einen Ordner, in dem noch etwas liegt, fragt PowerShell von selbst nach. So schützt es dich vor einem zu grossen Löschen. Lea tippt auch hier N:

      

      
Auf Deutsch: «Der Ordner hat Inhalt, und du hast -Recurse nicht angegeben. Wenn du weitermachst, ist alles darin weg.» Mit -Recurse fragt PowerShell nicht mehr und löscht den Ordner samt Inhalt. Darum zuerst die Probefahrt:

      

      
Nur eine Zeile, obwohl zwei Dateien im Ordner liegen (eine davon versteckt). Bei -Recurse nennt -WhatIf nur den Ordner. Was alles darin ist, zeigt dir Get-ChildItem Dokumente\Archiv -Recurse -Force (mit -Force auch versteckte Dateien). Schau also beides an.

      
Versteckte Dateien: Ohne -Force löscht auch -Recurse keine versteckten Dateien. Auf Leas Rechner liegt in Dokumente\Archiv die versteckte schatz.txt. Echtes pwsh 7 löscht bei Remove-Item Dokumente\Archiv -Recurse alles andere, lässt schatz.txt und damit den Ordner stehen und meldet:
        
Remove-Item: You do not have sufficient access rights to perform this operation or the item is hidden, system, or read only.
Remove-Item: Directory C:\Users\lea\Dokumente\Archiv cannot be removed because it is not empty.

        Auf Deutsch: «Die Datei ist versteckt, darum darf ich sie nicht löschen. Der Ordner ist darum nicht leer.» Erst -Recurse -Force nimmt alles mit. Der Simulator vereinfacht hier und löscht versteckte Dateien auch ohne -Force.

    

    
Vor jedem -Recurse: Prüf mit Get-Location, wo du bist. Remove-Item * -Recurse löscht alles am aktuellen Ort, was nicht versteckt ist. Im falschen Ordner ist das ein Unglück.

Inhalte lesen und schreiben

    

      
Lesen mit Get-Content

      
Get-Content liest eine Textdatei und gibt jede Zeile als eigenen Text aus.

      

      
Bei langen Dateien willst du oft nur den Anfang oder das Ende. -TotalCount 2 liest die ersten zwei Zeilen, -Tail 2 die letzten zwei. Das Ende einer Logdatei zeigt die neusten Einträge.

Statt -TotalCount darfst du auch -First oder -Head schreiben, statt -Tail auch -Last.

    

    

      
Schreiben: ersetzen oder anhängen?

      
Set-Content ersetzt den ganzen Inhalt. Add-Content hängt eine Zeile ans Ende. Beide legen die Datei an, wenn es sie noch nicht gibt.

      

      

      

      
Das dritte Set-Content hat beide Zeilen ersetzt. Eine Rückfrage gibt es dabei nicht.

    

    

      
Out-File und die Umleitung > und >>

      
Out-File schreibt in eine Datei, was sonst auf dem Bildschirm erscheinen würde, mit Tabelle und Kopfzeilen. Die Umleitung > macht dasselbe kürzer: Befehl > datei.txt ist gleichwertig zu Befehl | Out-File datei.txt. >> hängt an, wie Out-File -Append.

      

      
Set-Content schreibt dagegen nur den Text jedes Objekts, bei Dateien den vollen Pfad. Sieh den Unterschied:

Faustregel: Für Text, den du selbst schreibst (Notizen, Listen), nimm Set-Content und Add-Content. Willst du festhalten, was ein Befehl auf dem Bildschirm zeigt, nimm Out-File oder >.

    

    

      
Encoding: wie Buchstaben als Bytes gespeichert werden

      
Eine Datei speichert keine Buchstaben, sondern Zahlen (Bytes). Das Encoding ist die Tabelle, die festlegt, welche Bytes welcher Buchstabe sind. Für A bis Z sind sich fast alle Tabellen einig, für ä, ö, ü nicht. Liest ein Programm eine Datei mit der falschen Tabelle, erscheinen statt «ä» seltsame Zeichen.

      
PowerShell 7 schreibt mit allen Befehlen dieser Station UTF-8 ohne BOM, das heute übliche Format. (Die BOM ist ein kleines Kennzeichen am Dateianfang, das die Tabelle verrät.) Windows PowerShell 5.1 ist uneinheitlich:

      

        

          Standard-Encoding beim Schreiben von «ä» (in pwsh 7.6.1 und powershell.exe 5.1 nachgeprüft)
          
BefehlPowerShell 7Windows PowerShell 5.1

          
            
Out-File, >, >>UTF-8 ohne BOM (C3 A4)UTF-16 LE mit BOM (FF FE E4 00)

            
Set-Content, Add-ContentUTF-8 ohne BOM (C3 A4)ANSI, die Windows-Codepage (E4)

          
        

      

      
Unterschied 5.1: Wer in Windows PowerShell 5.1 eine Datei mit Set-Content anlegt und dann mit >> ergänzt, mischt zwei Encodings in einer Datei. Die angehängte Zeile erscheint danach als «z w e i» mit Lücken. Brauchst du ein bestimmtes Format, gib es mit -Encoding utf8 ausdrücklich an. Prüfen kannst du das nur in powershell.exe, der Simulator verhält sich wie PowerShell 7.

    Lösungsfilm · Erst zuschauen, dann testen
    
Leas Logarchiv

    
Der Leiter Informatik gibt Lea einen Auftrag: (a) Lege im Ordner Logs einen Ordner Archiv an. (b) Verschiebe die Monatslogs von Juli bis September und das Backup-Log vom Juni hinein. (c) Schreib eine Datei liesmich.txt mit zwei Zeilen ins Archiv. (d) Das Juli-Log darf weg, aber prüf zuerst. (e) Benenne das Archiv in Archiv-2026 um.

    
Jede Szene zeigt einen Befehl und die Ausgabe des Simulators auf Leas Rechner.

    

    

      Lösung zum Nachlesen
      

        
New-Item Logs\Archiv -ItemType Directory
Move-Item Logs\app-2026-0*.log Logs\Archiv
Move-Item Logs\backup-2026-06.log Logs\Archiv
Set-Content Logs\Archiv\liesmich.txt 'Archiv vom 2.11.2026'
Add-Content Logs\Archiv\liesmich.txt 'Logs älter als 30 Tage'
Remove-Item Logs\Archiv\app-2026-07.log -WhatIf
Remove-Item Logs\Archiv\app-2026-07.log
Rename-Item Logs\Archiv Archiv-2026

        
Endstand: Im Ordner Logs liegen der Ordner Archiv-2026, app-2026-10.log, app.log und sync-fehler.log. Im Archiv liegen app-2026-08.log, app-2026-09.log, backup-2026-06.log und liesmich.txt (47 Bytes).

        
Eigene Lösung, nicht vom Dozenten bestätigt. Alle Befehle in PowerShell 7.6 in einem nachgebauten Ordner geprüft.

      

    

  


  
  

    Typische Fehler
    
Die häufigsten Stolpersteine

    
Ordner ohne -Recurse kopiert: Copy-Item Dokumente Sicherung legt nur einen leeren Ordner an, ohne Fehlermeldung. Für den Inhalt brauchst du -Recurse.

    
Zielordner fehlt: Move-Item foto.jpg Fotos ohne bestehenden Ordner Fotos benennt die Datei in Fotos um. Bei mehreren Dateien (Move-Item *.jpg Fotos) wird die erste zur Datei Fotos, für alle weiteren meldet PowerShell Cannot create a file when that file already exists. («Eine Datei mit diesem Namen gibt es schon»; auf einem deutschen Windows steht die Meldung auf Deutsch). Zuerst New-Item Fotos -ItemType Directory.

    
Zweimal mit -Recurse kopiert: Gibt es den Zielordner schon, landet die Kopie darin: Sicherung\Dokumente statt Sicherung.

    
> statt >>: Ein einziges Zeichen entscheidet, ob die alte Datei weg ist. 'Neu' > notizen.txt ersetzt den ganzen Inhalt, 'Neu' >> notizen.txt hängt an.

    
Zusammengeklebte Zeilen: New-Item -Value schreibt den Text ohne Zeilenende. Ein folgendes Add-Content klebt direkt daran:
      

      Willst du danach Zeilen anhängen, lege die Datei mit Set-Content an. Set-Content und Add-Content schliessen jede Zeile ab.

    
Rename-Item mit Pfad: Der neue Name ist nur ein Name. Rename-Item a.txt Archiv\b.txt scheitert. Verschieben ist Sache von Move-Item.

    
Copy-Item überschreibt still: Gibt es die Zieldatei schon, ersetzt Copy-Item sie ohne Rückfrage. Move-Item dagegen meldet einen Fehler und lässt beide Dateien, wie sie sind.

    
-WhatIf vergessen und am falschen Ort: Remove-Item *.txt löscht alle Textdateien am aktuellen Ort. Prüf zuerst mit Get-Location, wo du bist, und probe mit -WhatIf.

Unterschiede zu Windows PowerShell 5.1

      
    
        
  • Out-File, > und >> schreiben in 5.1 UTF-16 LE mit BOM, in 7 UTF-8 ohne BOM.
    •

    • 
        
  • Mischst du in 5.1 Set-Content und >> in einer Datei, entstehen kaputte Zeilen. Mit -Encoding utf8 legst du das Format fest (in 5.1 mit BOM).
    • 
        
  • Get-ChildItem Bilder | Set-Content bilder.txt schreibt in 5.1 nur die Dateinamen, in 7 die vollen Pfade.
    •
