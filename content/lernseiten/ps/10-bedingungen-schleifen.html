Entscheiden und wiederholen

Denk an Lea am Montagmorgen. Auf ihrem Pult liegt ein Stapel Briefe. Sie nimmt einen Brief nach dem anderen (das ist eine Schleife). Bei jedem Brief fragt sie sich: «Ist das eine Rechnung?» (das ist eine Bedingung). Ist die Antwort ja, legt sie ihn in die Ablage Finanzen, sonst in die Ablage Post (das ist eine Verzweigung). Was sie mit jedem Brief tut, steht auf einem Merkzettel (das ist ein Block).

PowerShell kennt genau diese Bausteine. Ein Skript ist nichts anderes als eine Reihe von Befehlen, die PowerShell von oben nach unten abarbeitet. Bedingungen und Schleifen ändern diesen Weg: Sie überspringen Zeilen oder wiederholen sie.

Block{ 'Hallo' }

Der Merkzettel. Befehle in geschweiften Klammern gehören zusammen und laufen gemeinsam.

Bedingung($x -gt 5)

Die Ja-Nein-Frage in runden Klammern. Ihr Ergebnis ist $true oder $false.

Verzweigungif · switch

Die Weggabelung. Je nach Antwort läuft der eine oder der andere Block.

Schleifeforeach · for · while

Der Stapel. Derselbe Block läuft mehrmals, einmal pro Element oder solange eine Bedingung gilt.

Schritt 1 · Vom Auftrag zum Skript

Leas erstes Skript Stück für Stück

Der Leiter Informatik will wissen, welche Logdateien gross sind. Lea baut ein kleines Skript in vier Schritten. Nach jedem Schritt siehst du, was PowerShell 7 ausgibt. Fahre über ein unterstrichenes Satzstück oder tippe darauf: Die passende Zeile des Skripts leuchtet auf.

Schritt 2 · Bedingungen mit if

Wenn, sonst wenn, sonst

Der Block { }

Geschweifte Klammern fassen Befehle zu einem Block zusammen. Den Block kennst du schon aus Where-Object { $_.Length -gt 1MB }. Dort heisst er Skriptblock: ein Stück Code, das du wie einen Wert weitergeben und später ausführen kannst. Speicherst du einen Skriptblock in einer Variable, führt ihn der Aufrufoperator & aus, so oft du willst.


      
Bei if, foreach und den anderen Schlüsselwörtern dieser Station sieht der Block gleich aus. PowerShell gibt ihn aber nicht weiter, sondern führt ihn an Ort und Stelle aus, sobald er an der Reihe ist (bei if nur, wenn die Bedingung passt). Microsoft nennt ihn darum genauer einen Anweisungsblock.

    


    

      
if und else

      
Nach if steht die Bedingung in runden Klammern, danach der Block in geschweiften. Ist die Bedingung wahr, läuft der Block. Sonst läuft der Block nach else. Das else darfst du auch weglassen: Dann passiert bei «falsch» einfach nichts.

      
$x = 7
if ($x -gt 5) {
    'gross'
}
else {
    'klein'
}

      

      
Die Bedingung ist ein Vergleich aus Station 07 und 09: -gt, -eq, -like, verbunden mit -and oder -or. Auch ein Befehl darf drinstehen. Test-Path liefert zum Beispiel $true, wenn ein Ordner existiert:

      

    


    

      
Mehrere Stufen mit elseif

      
Mit elseif hängst du weitere Fragen an. PowerShell prüft sie von oben nach unten und nimmt den ersten Block, dessen Bedingung wahr ist. Alle späteren überspringt es, auch wenn sie ebenfalls wahr wären.

      
$z = 15
if ($z -gt 10) {
    'über 10'
}
elseif ($z -gt 5) {
    'über 5'
}
else {
    'klein'
}

      

      
15 ist auch grösser als 5. Trotzdem erscheint nur «über 10»: Die erste passende Stufe gewinnt.

    


    

      
Was zählt als wahr?

      
In der Klammer muss nicht unbedingt $true oder $false stehen. PowerShell wandelt jeden Wert in wahr oder falsch um. Die Regel: Leer, null und die Zahl 0 sind falsch. Fast alles andere ist wahr, auch der Text 'False'.

      

        

          Wert in der Bedingung (alle Ergebnisse in pwsh 7.6 mit [bool] geprüft)
          
Wertgilt alsWarum

          
            
0falschdie Zahl null

            
''falschleerer Text

            
$nullfalschgar kein Wert

            
@()falschleere Liste, zum Beispiel wenn ein Befehl nichts findet

            
'0'wahrein Text mit einem Zeichen, nicht die Zahl 0

            
'False'wahrein Text mit fünf Zeichen

            
' 'wahrein Leerzeichen ist auch ein Zeichen

          
        

      

      
Darum funktioniert dieser kurze Test: Findet Get-ChildItem nichts, ist das Ergebnis leer und damit falsch.

      

    


    

      
Einrückung und Lesbarkeit

      
Ob du einen Block auf eine Zeile schreibst oder über mehrere Zeilen verteilst und einrückst, spielt für PowerShell keine Rolle. Beide Fassungen unten tun dasselbe. Für dich und deine Kolleginnen ist die rechte viel leichter zu lesen: Jeder Block ist um vier Leerzeichen eingerückt, jede schliessende Klammer steht unter dem Wort, das den Block geöffnet hat.

      

        

          
Läuft, ist aber schwer zu lesen

          
foreach ($datei in $dateien) { if ($datei.Length -gt 1MB) { "$($datei.Name): gross" } else { "$($datei.Name): klein" } }

        

        

          
Gleich, aber eingerückt

          
foreach ($datei in $dateien) {
    if ($datei.Length -gt 1MB) {
        "$($datei.Name): gross"
    }
    else {
        "$($datei.Name): klein"
    }
}

        

      

      
Tipp: In der Konsole sind Einzeiler praktisch. In einer Skriptdatei schreibst du eingerückt. Fehlt eine schliessende Klammer, wartet die Konsole mit >> auf den Rest. Tippe die Klammer nach oder brich mit Ctrl + C ab.

    

  


  
  

    Schritt 3 · Viele Fälle mit switch
    
switch: die Sortierstation

    
Stell dir die Sortieranlage der Post vor: Ein Brief kommt an, die Anlage liest die Postleitzahl und schickt ihn in das passende Fach. switch macht dasselbe mit einem Wert. Statt einer langen Kette aus if und elseif schreibst du die Fälle untereinander.


    

      
Einfacher switch

      
In den runden Klammern steht der Wert, den switch prüft. Im Block folgt Fall für Fall: links der Vergleichswert, rechts in { } was passieren soll. default ist das Fach «alles andere», wie else.

      
switch (3) {
    1       { 'eins' }
    3       { 'drei' }
    default { 'andere Zahl' }
}

      

      
Texte vergleicht switch ohne Rücksicht auf Gross- und Kleinschreibung, genau wie -eq. Willst du sie beachten, schreibst du switch -CaseSensitive.

      

    


    

      
Mehrere Treffer und break

      
Anders als if/elseif hört switch nach dem ersten Treffer nicht auf. Es prüft alle Fälle und führt jeden passenden Block aus. Willst du nach dem ersten Treffer aufhören, schreibst du break in den Block.

      

        

          
ohne break: beide Fälle laufen

          

        

        

          
mit break: Schluss nach dem ersten

          

        

      

    


    

      
Muster mit -Wildcard

      
Mit switch -Wildcard dürfen die Fälle Platzhalter enthalten, wie bei -like: * für beliebig viele Zeichen, ? für genau eines. So teilt Lea Dateien nach Namen ein. Auch hier laufen alle passenden Fälle:

      
switch -Wildcard ('app-2026-07.log') {
    'app*'  { 'App' }
    '*.log' { 'Log' }
}

      

    


    

      
Eine ganze Liste prüfen

      
Gibst du switch eine Liste, prüft es jedes Element einzeln, wie eine kleine Schleife. Im Block steht das aktuelle Element in $_. Hier bekommt switch alle Namen aus dem Ordner Downloads:

      
switch -Wildcard ((Get-ChildItem Downloads).Name) {
    '*.pdf' { "Dokument: $_" }
    '*.exe' { "Programm: $_" }
    default { "Anderes:  $_" }
}

      

      
Merke: (Get-ChildItem Downloads).Name holt die Namen aller Dateien als Liste (Member-Aufzählung aus Station 06). Die runden Klammern sorgen dafür, dass der Befehl zuerst läuft.

    

  


  
  

    Schritt 4 · Wiederholen
    
Schleifen: foreach, ForEach-Object, for, while


    

      
foreach: für jedes Element

      
Das foreach-Statement geht eine Sammlung Element für Element durch. In der Klammer steht zuerst ein Name für das aktuelle Element, dann in, dann die Sammlung. Den Namen wählst du selbst; $datei für Dateien, $dienst für Dienste macht das Skript lesbar.

      
foreach ($datei in Get-ChildItem Downloads) {
    $datei.Name
}

      

      
Du kannst Variablen von ausserhalb der Schleife benutzen, zum Beispiel einen Zähler. $gross++ zählt eins dazu:

      
$gross = 0
foreach ($datei in Get-ChildItem Logs) {
    if ($datei.Length -gt 1MB) {
        $gross++
    }
}
"Grosse Dateien: $gross"

      

    


    

      
ForEach-Object: dasselbe in der Pipeline

      
ForEach-Object ist ein Cmdlet. Es steht hinter einem | und bekommt die Objekte aus der Pipeline. Das aktuelle Objekt heisst hier immer $_, wie bei Where-Object.

      
Get-ChildItem Downloads | ForEach-Object { $_.Name }

      
Die Ausgabe ist dieselbe wie oben. Für eine einzelne Eigenschaft gibt es eine Kurzform ohne Klammern: Get-ChildItem Downloads | ForEach-Object Name. Achtung: In der Pipeline ist foreach eine Abkürzung (Alias) für ForEach-Object. Am Anfang eines Befehls (am Zeilenanfang oder nach ;) ist es das Statement.

      

        

          foreach-Statement und ForEach-Object im Vergleich
          
foreach ($x in …) { }… | ForEach-Object { }

          
            
ArtSchlüsselwort der SpracheCmdlet in der Pipeline

            
aktuelles Elementdein Name, z. B. $dateiimmer $_

            
Ablaufholt zuerst die ganze Sammlung, dann beginnt die erste Rundeverarbeitet jedes Objekt, sobald es ankommt

            
weitergeben mit |nicht direkt (Fehler), nur mit $( … ) darumja, wie jedes Cmdlet

            
breakbeendet die Schleifebeendet die ganze Pipeline und alles danach in der Zeile (vermeiden)

          
        

      

      
Den Unterschied im Ablauf siehst du mit Write-Host, das sofort auf den Bildschirm schreibt. Beim Statement holt PowerShell zuerst alle drei Zahlen. In der Pipeline wandert jede Zahl gleich weiter:

      

        

          
foreach-Statement

          
foreach ($n in (1..3 | ForEach-Object { Write-Host "hole $_"; $_ })) {
    Write-Host "verarbeite $n"
}

          
hole 1
hole 2
hole 3
verarbeite 1
verarbeite 2
verarbeite 3

        

        

          
ForEach-Object in der Pipeline

          
1..3 | ForEach-Object { Write-Host "hole $_"; $_ } |
    ForEach-Object { Write-Host "verarbeite $_" }

          
hole 1
verarbeite 1
hole 2
verarbeite 2
hole 3
verarbeite 3

        

      

      
Beide Ausgaben stammen aus echtem pwsh 7.6. Der Simulator arbeitet die Pipeline Stufe für Stufe ab und zeigt rechts zuerst alle «hole»-Zeilen.

      
Faustregel: Kommen die Objekte sowieso aus einer Pipeline, nimm ForEach-Object. Hast du die Daten schon in einer Variable und brauchst break oder continue, nimm das foreach-Statement.

      
Nur in 7: ForEach-Object -Parallel { … } verarbeitet mehrere Objekte gleichzeitig. Das lohnt sich bei langsamen Aufgaben, zum Beispiel vielen Netzwerkabfragen. Die Reihenfolge der Ausgabe ist dann nicht mehr fest. Windows PowerShell 5.1 kennt -Parallel nicht und meldet einen Fehler. Für den Lernpfad brauchst du es nicht.

    


    

      
for: zählen

      
Die for-Schleife ist ein Zählwerk. In der Klammer stehen drei Teile, getrennt durch Strichpunkte: der Start ($i = 3), die Bedingung ($i -gt 0, solange wahr, geht es weiter) und der Schritt nach jeder Runde ($i-- zählt eins ab).

      
for ($i = 3; $i -gt 0; $i--) {
    "Noch $i"
}
'Start!'

      

    


    

      
while: solange

      
while wiederholt den Block, solange die Bedingung wahr ist. Es prüft vor jeder Runde. Ist die Bedingung schon am Anfang falsch, läuft der Block kein einziges Mal. Wichtig: Im Block muss sich etwas ändern, sonst läuft die Schleife ewig.

      
$i = 0
while ($i -lt 3) {
    $i++
    "Runde $i"
}

      

      
Verwandt ist do { … } while (…). Es prüft erst nach der Runde und läuft darum mindestens einmal:

      

    


    

      
break und continue

      
break heisst «Schluss, raus aus der Schleife». continue heisst «diese Runde überspringen, weiter mit der nächsten».

      

        

          
continue bei 3: die 3 fehlt

          

        

        

          
break bei 3: Schluss

          

        

      

      
Typischer Einsatz von break: die erste passende Datei suchen. Sobald sie gefunden ist, muss die Schleife nicht weiter suchen.

      

      
Bei zwei Schleifen ineinander verlässt break nur die innere. Die äussere läuft weiter:

      

      
Achtung im switch: Steht break in einem switch, verlässt es nur den switch, nicht die Schleife darum herum. Im Selbsttest kommt das vor.

    Typische Fehler
    
    Die häufigsten Stolpersteine
    
    
    = statt -eq: In if ($anzahl = 10) vergleicht PowerShell nicht, sondern weist zu. $anzahl ist danach 10, und weil 10 als wahr gilt, läuft der Block immer. Für «ist gleich» schreibst du -eq.
    
    
    > statt -gt: if ($x > 3) ist kein Vergleich, sondern eine Umleitung. PowerShell schreibt den Wert von $x still in eine neue Datei namens 3, und die Bedingung ist leer, also falsch. Lösche die Datei danach mit Remove-Item 3.
      
    
    
    
    
    $_ im foreach-Statement: foreach ($datei in Get-ChildItem Logs) { $_.Name } gibt nichts aus. $_ gehört zur Pipeline. Im Statement heisst das aktuelle Element so, wie du es in der Klammer genannt hast: $datei.Name.
    
    
    foreach-Statement in die Pipeline: Hinter die schliessende Klammer eines Statements darfst du kein | setzen.
      
    PS C:\Users\lea> foreach ($z in 1..3) { $z * 10 } | Measure-Object
ParserError:
Line |
   1 |  foreach ($z in 1..3) { $z * 10 } | Measure-Object
     |                                   ~
     | An empty pipe element is not allowed.
    
      Auf Deutsch: «Vor dem Strich steht nichts, was in die Pipeline gehört.» Pack das Statement in $( … ) oder nimm ForEach-Object:
      
    
    
    
    
    break in ForEach-Object: In der Pipeline gibt es keine Schleife, die break verlassen könnte. PowerShell bricht darum die ganze Pipeline ab und alles, was in der Zeile oder im Skript danach kommt. In pwsh 7 gibt 1..5 | ForEach-Object { if ($_ -eq 3) { break }; $_ }; 'danach' nur 1 und 2 aus, «danach» erscheint nie. Willst du in ForEach-Object nur ein Objekt überspringen, nimm return. Das wirkt dort wie continue.
    
    
    Endlosschleife: $i = 0; while ($i -lt 3) { "Runde $i" } hört nie auf, weil sich $i nie ändert. Im Block muss etwas die Bedingung irgendwann falsch machen ($i++). In echter PowerShell stoppst du eine hängende Schleife mit Ctrl + C.
    
    
    switch mit mehreren Treffern: switch -Wildcard ('rechnung-2026-09.pdf') { 'rechnung*' { 'Rechnung' } '*.pdf' { 'PDF' } } gibt beides aus. Soll nur der erste Treffer zählen, gehört break in den Block.
    
    
    else auf neuer Zeile in der Konsole: In einer Skriptdatei darf else auf der nächsten Zeile stehen. Tippst du in der Konsole if (…) { … } und drückst Enter, ist der Befehl aber fertig und läuft. Ein else in der nächsten Eingabe kennt PowerShell dann nicht: The term 'else' is not recognized …. In der Konsole schreibst du } else { auf dieselbe Zeile.

    whilewiederholen, solange die Bedingung wahr ist (prüft vorher)while ($i -lt 3) { $i++ }
    
          
    do … whilewiederholen, prüft nachher, läuft mindestens einmaldo { $i++ } while ($i -lt 3)
    
          
    breakSchleife oder switch sofort verlassenif ($z -eq 3) { break }
    
          
    continuediese Runde überspringenif ($z -eq 3) { continue }
    
            
      
    
    
    
    
      
      
    • Runde Klammern für die Bedingung, geschweifte für den Block.
      • 
      
    • if/elseif nimmt die erste wahre Stufe, switch führt alle Treffer aus, ausser du schreibst break.
      • 
      
    • 0, leerer Text, $null und leere Listen sind falsch. Der Text 'False' ist wahr.
      • 
      
    • Im foreach-Statement heisst das Element, wie du es nennst; in ForEach-Object heisst es $_.
      • 
      
    • break verlässt die innerste Schleife (oder den switch), continue springt zur nächsten Runde.
      • 
      
    • Im Block muss sich etwas ändern, sonst läuft while ewig.
      • 
      
    • Rücke jeden Block um vier Leerzeichen ein. Das liest sich wie ein Inhaltsverzeichnis.
      • 
    
    
    
    
      
    Unterschiede zu Windows PowerShell 5.1
    
      
      
        
    • ForEach-Object -Parallel gibt es nur in 7. In 5.1 meldet ForEach-Object einen Fehler zu den Parametern.
      • 
        
    • Die Kurzform $x -gt 5 ? 'gross' : 'klein' (ternärer Operator, ein if/else in einer Zeile) gibt es erst ab 7. In 5.1 meldet PowerShell «Unexpected token '?'»; dort schreibst du if und else aus.
      • 
        
    • if, switch, foreach, for, while, break und continue funktionieren in 5.1 gleich.
