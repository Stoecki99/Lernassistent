PS · Teil 3 · Pipeline und Objekte

Ausgeben, formatieren, exportieren

Das Personalamt will von Lea die Mitarbeitenden der Informatik als Liste für Excel. Der Leiter Informatik möchte wissen, wie viele MB die Logdateien belegen. Du lernst, Ergebnisse schön auf den Bildschirm zu bringen, sie als CSV oder JSON in eine Datei zu schreiben und eigene Spalten auszurechnen.

Lernziele

  • Du stellst Objekte mit Format-Table, Format-List und Format-Wide dar und wählst die Eigenschaften selbst.
  • Du erklärst, warum ein Format-Cmdlet immer am Schluss der Pipeline steht.
  • Du exportierst mit Export-Csv (auch mit Semikolon für Excel) und liest mit Import-Csv wieder ein. Du weisst, dass dabei alle Werte zu Text werden.
  • Du wandelst Objekte mit ConvertTo-Json in JSON um und wählst die passende Tiefe.
  • Du baust eine berechnete Eigenschaft, zum Beispiel die Dateigrösse in MB.

Schaufenster oder Versandkarton?

Denk an einen Laden. Im Schaufenster liegt die Ware hübsch angeordnet, damit Leute sie anschauen. Verschickt der Laden etwas, packt er die Ware in einen beschrifteten Karton, damit jemand anderes sie auspacken und weiterverwenden kann. Niemand schickt das Schaufenster per Post.

In PowerShell ist es gleich. Am Ende der Pipeline (Station 07) stehen Objekte. Du kannst sie für dich auf dem Bildschirm darstellen (Schaufenster) oder sie in eine Datei verpacken, damit Excel, ein Web-Dienst oder ein anderes Skript sie liest (Versandkarton).

FormatierenFormat-Table

Das Schaufenster. Es bestimmt, wie die Objekte auf dem Bildschirm aussehen: als Tabelle, als Liste oder breit in Spalten.

ExportierenExport-Csv

Der Versandkarton. Die Daten gehen in eine Datei, die andere Programme öffnen können.

CSV"Name";"Pensum"

Eine Tabelle als reiner Text: eine Zeile pro Objekt, die Werte durch ein Trennzeichen getrennt. Excel kann sie öffnen.

JSON{ "Name": "Keller" }

Karteikarten, die selbst wieder Karteikarten enthalten dürfen. Web-Dienste und Einstellungsdateien nutzen dieses Format.

Berechnete Eigenschaft@{ Name = 'MB'; … }

Eine Spalte, die du selbst ausrechnest, wie eine Formelspalte in Excel. Zum Beispiel die Grösse in MB statt in Bytes.

Kurz üben: Schaufenster oder Versandkarton?

Wohin geht das Ergebnis dieses Befehls: nur auf den Bildschirm oder in eine Datei für andere Programme?

Schritt 2 · Format-Table, Format-List, Format-Wide

Das Schaufenster einrichten

Was PowerShell von selbst zeigt

Ohne Format-Cmdlet entscheidet PowerShell selbst. Für Dateien, Dienste und Prozesse gibt es fertige Ansichten (Station 06). Für eigene Objekte wie die Zeilen einer CSV-Datei gilt eine einfache Regel: bis vier Eigenschaften eine Tabelle, ab fünf eine Liste.

Vier Eigenschaften: Tabelle


        

        

          
Fünf Eigenschaften: Liste

          

        

      

      
Die Mitarbeitendenliste hat fünf Spalten (Name, Vorname, Abteilung, Pensum, Eintritt). Darum erscheint sie ohne Format-Cmdlet als lange Liste. Willst du sie anders sehen, sagst du es PowerShell.

    


    

      
Format-Table: eine Tabelle

      
Format-Table zeigt jedes Objekt als Zeile, jede Eigenschaft als Spalte. Mit -Property wählst du die Spalten und ihre Reihenfolge. Den Parameternamen darfst du weglassen, die Namen trennst du mit Komma.

      
Import-Csv Berichte\mitarbeitende.csv | Format-Table -Property Name, Vorname, Abteilung

      

      
-AutoSize macht jede Spalte so breit, wie ihr längster Wert es braucht. Bei Leas kurzen Listen sieht das Ergebnis gleich aus. Bei langen Werten verhindert -AutoSize, dass PowerShell Text abschneidet und mit … endet.

      
Get-ChildItem Logs | Format-Table Name, Length -AutoSize

      
Der Alias von Format-Table heisst ft. In der Konsole ist er praktisch, im Skript schreibst du den vollen Namen (Station 02).

    


    

      
Format-List: eine Liste

      
Format-List zeigt jede Eigenschaft auf einer eigenen Zeile, «Name : Wert». Das passt, wenn du wenige Objekte mit vielen Eigenschaften genau lesen willst, zum Beispiel Leas eigenen Eintrag.

      
Import-Csv Berichte\mitarbeitende.csv | Where-Object Name -eq Keller | Format-List

      

      
Auch hier kannst du Eigenschaften nennen: Format-List Name, Pensum. Mit Format-List * siehst du alle Eigenschaften, auch die, die die Standardansicht versteckt. Das kennst du aus Station 06. Der Alias ist fl.

    


    

      
Format-Wide: nur ein Wert, dafür breit

      
Format-Wide zeigt von jedem Objekt eine einzige Eigenschaft und verteilt die Werte auf mehrere Spalten, wie ein Namensverzeichnis. -Column legt die Anzahl Spalten fest.

      
Import-Csv Berichte\mitarbeitende.csv | Format-Wide Name -Column 4

      

    


    

      
Die wichtigste Regel: Format-Cmdlets immer zuletzt

      
Ein Format-Cmdlet richtet das Schaufenster ein. Dafür macht es aus deinen Objekten Formatierungsobjekte: Anweisungen wie «hier beginnt eine Tabelle», «das ist eine Zeile», «hier endet sie». Die Eigenschaften Name oder Pensum haben diese Objekte nicht mehr. Nur die Konsole versteht sie.

      
Import-Csv Berichte\mitarbeitende.csv | Format-Table Name, Pensum |
  ForEach-Object { $_.GetType().Name } | Select-Object -Unique

      

      
Statt acht Mitarbeitenden kommen fünf Sorten Bauanleitung heraus: Start, Gruppenstart, Zeile (achtmal), Gruppenende, Ende. Was nach Format-Table kommt, arbeitet mit diesen Bauanleitungen und nicht mehr mit deinen Daten. Zwei Beispiele:

    Schritt 3 · Out-File, Export-Csv, Import-Csv
    
Der Versandkarton CSV


    

      
Out-File: der Bildschirm als Textdatei

      
Out-File schreibt genau den Text in eine Datei, der sonst auf dem Bildschirm stünde (Station 05). Das ist gut für eine Notiz oder ein Protokoll, das ein Mensch liest.

      

      
Für Excel oder ein anderes Programm taugt das wenig. Die Datei enthält nur Text mit Leerzeichen, keine Spalten, die ein Programm sicher trennen kann. Dafür gibt es CSV.

    


    

      
Export-Csv: Objekte als Tabelle in eine Datei

      
CSV heisst comma-separated values, «durch Komma getrennte Werte». Export-Csv schreibt eine Kopfzeile mit den Namen der Eigenschaften und danach eine Zeile pro Objekt. Jeder Wert steht in Anführungszeichen. Wie das aussieht, zeigt dir ConvertTo-Csv: Es macht dasselbe, schreibt aber in die Konsole statt in eine Datei.

      
Import-Csv Berichte\mitarbeitende.csv | Select-Object -First 2 | ConvertTo-Csv

      

      
Mit Export-Csv bericht.csv statt ConvertTo-Csv landen dieselben Zeilen in der Datei bericht.csv. Eine bestehende Datei überschreibt Export-Csv ohne Nachfrage. -Append hängt an, -NoClobber verhindert das Überschreiben.

    


    

      
Semikolon für Excel in der Schweiz

      
Excel mit Schweizer Einstellungen erwartet in CSV-Dateien ein Semikolon als Trennzeichen, kein Komma. Öffnest du eine Komma-Datei per Doppelklick, steht oft jede Zeile in einer einzigen Spalte. Darum gibst du das Trennzeichen mit -Delimiter ';' an. Das Semikolon gehört in Anführungszeichen, sonst hält PowerShell es für das Ende des Befehls.

      
Import-Csv Berichte\mitarbeitende.csv | Select-Object -First 2 | ConvertTo-Csv -Delimiter ';'

      

      
Es gibt auch -UseCulture: Dann nimmt PowerShell das Listentrennzeichen der Ländereinstellung. Unter de-CH ist das auf Windows ebenfalls ein Semikolon. -Delimiter ';' ist eindeutiger, weil es auf jedem Rechner gleich wirkt.

    


    

      
Encoding: Umlaute sicher ablegen

      
Ein Encoding legt fest, wie Buchstaben als Bytes in der Datei stehen. Das zählt bei Umlauten wie im Namen Bühler. PowerShell 7 schreibt mit Export-Csv standardmässig UTF-8 ohne Kennzeichen am Dateianfang (utf8NoBOM). Viele Programme lesen das richtig. Excel erkennt UTF-8 beim Doppelklick aber oft nur mit Kennzeichen, dem BOM (byte order mark). Sonst erscheint BÃ¼hler.

      
Import-Csv Berichte\mitarbeitende.csv |
  Export-Csv Berichte\fuer-excel.csv -Delimiter ';' -Encoding utf8BOM

      
Unterschied 5.1: Windows PowerShell 5.1 schreibt mit Export-Csv standardmässig ASCII. Umlaute gehen dabei verloren und werden zu ?. Dazu kommt eine Zeile #TYPE … am Anfang, wenn du -NoTypeInformation weglässt. In 5.1 schreibst du darum -NoTypeInformation -Encoding UTF8 dazu (in 5.1 heisst UTF8 UTF-8 mit BOM). In 7 ist -NoTypeInformation der Standard.

      
PS C:\Users\lea> Import-Csv Berichte\mitarbeitende.csv -Encoding UTF8 | Select-Object -Last 1 | Export-Csv alt.csv
PS C:\Users\lea> Get-Content alt.csv
#TYPE Selected.System.Management.Automation.PSCustomObject
"Name","Vorname","Abteilung","Pensum","Eintritt"
"B?hler","Jonas","Informatik","100","2020-09-01"

      
Ausgabe aus Windows PowerShell 5.1 (von Hand übernommen, der Simulator ist pwsh 7).

    


    

      
Import-Csv: aus Text werden wieder Objekte

      
Import-Csv liest eine CSV-Datei und macht aus jeder Zeile ein Objekt. Die Kopfzeile liefert die Namen der Eigenschaften. Darum funktionieren danach Where-Object, Sort-Object und Select-Object wie gewohnt. Hat die Datei Semikolons, sagst du es auch beim Einlesen: Import-Csv datei.csv -Delimiter ';'.

      
Ein CSV-Text weiss aber nicht, was eine Zahl ist. Import-Csv liefert jeden Wert als Text (Typ String), auch das Pensum:

      

      
Das hat Folgen. Rechnen klebt Texte zusammen, und Vergleiche laufen Zeichen für Zeichen wie im Telefonbuch. "100" kommt dann vor "70", weil 1 vor 7 steht:

      

      

      
Wer «unter 70 Prozent» wollte, bekommt neben Frei und Gerber auch die vier Personen mit 100. Die Lösung: Wandle den Text vor dem Vergleich in eine Zahl um. [int] heisst «als ganze Zahl» (mehr dazu in Station 09). Das geht nur im Skriptblock:

      

      
Tipp: Beim Sortieren gilt dasselbe. Sort-Object { [int]$_.Pensum } sortiert nach Zahl, Sort-Object Pensum nach Text.

    

  


  
  

    Schritt 4 · ConvertTo-Json, ConvertFrom-Json, HTML
    
JSON: Karteikarten in Karteikarten


    

      
ConvertTo-Json

      
JSON (JavaScript Object Notation) schreibt jedes Objekt in geschweifte Klammern { }, jede Eigenschaft als "Name": Wert. Mehrere Objekte stehen in eckigen Klammern [ ], das ist eine Liste. ConvertTo-Json gibt den JSON-Text aus. In eine Datei schreibst du ihn mit Out-File oder Set-Content.

      
Import-Csv Berichte\mitarbeitende.csv | Select-Object -First 2 Name, Vorname | ConvertTo-Json

      

      
-Compress lässt Leerzeichen und Zeilenumbrüche weg. Das spart Platz, ist aber schwer zu lesen:

      

      
Siehst du "80" mit Anführungszeichen? Das Pensum kam aus der CSV-Datei und ist darum Text. JSON zeigt das ehrlich an.

    


    

      
Die Tiefe: Standard 2

      
Im Unterschied zu CSV kann JSON verschachteln: Eine Abteilung hat eine Leitung, die Leitung hat Kontaktdaten, die Kontaktdaten haben eine Adresse. Jede Karte in einer Karte ist eine Ebene tiefer. ConvertTo-Json geht standardmässig nur 2 Ebenen tief. Was tiefer liegt, wird zu einem flachen Text.

      
$abt = [pscustomobject]@{ Name = 'Informatik'; Leitung = [pscustomobject]@{ Name = 'Keller'
  Kontakt = [pscustomobject]@{ Telefon = '201'; Adresse = [pscustomobject]@{ Ort = 'Wolkenried' } } } }
$abt | ConvertTo-Json

      
[pscustomobject]@{ … } baut ein eigenes Objekt mit den Eigenschaften in den Klammern. Mehr dazu in Station 09.

      

      

      
PowerShell 7 warnt: «Resulting JSON is truncated», auf Deutsch «Das JSON ist abgeschnitten, die eingestellte Tiefe 2 reicht nicht». Die Adresse steht nur noch als Text @{Ort=Wolkenried} da. Mit -Depth erlaubst du mehr Ebenen (höchstens 100):

      

      
Unterschied 5.1: Windows PowerShell 5.1 kürzt genauso auf Tiefe 2, aber ohne Warnung. Die Daten fehlen still. Ausserdem rückt 5.1 anders ein, und ein Datum erscheint als "\/Date(1785535140000)\/" statt als lesbares "2026-07-31T23:59:00+02:00".

    


    

      
ConvertFrom-Json: aus JSON werden Objekte

      
Der Rückweg heisst ConvertFrom-Json. Anders als bei CSV kennt JSON Zahlen und true/false. Eine Zahl ohne Anführungszeichen bleibt darum eine Zahl, und du kannst mit ihr rechnen:

      

      
Vergleiche mit CSV: Dort ergab Pensum + 20 den Text 8020. Eine JSON-Datei liest du mit Get-Content datei.json -Raw | ConvertFrom-Json. -Raw liest die Datei als einen einzigen Text statt Zeile für Zeile.

    


    

      
Kurz erwähnt: HTML und Out-GridView

      
ConvertTo-Html macht aus Objekten eine HTML-Tabelle für den Browser. -Fragment liefert nur die Tabelle, ohne den Rest einer Webseite:

      

      
Mit | Out-File team.html dahinter öffnest du das Ergebnis im Browser. Out-GridView zeigt Objekte in einem Fenster mit Suchfeld und sortierbaren Spalten. Das gibt es nur unter Windows. Im Simulator ist es nicht nachgebaut, probier es auf deinem eigenen Rechner: Import-Csv Berichte\mitarbeitende.csv | Out-GridView.

    

  


  
  

    Schritt 5 · Eigene Spalten ausrechnen
    
Berechnete Eigenschaften

    
Leas Chef will die Grösse der Logdateien in MB, nicht in Bytes. Eine Eigenschaft MB haben Dateien nicht. Du baust sie selbst, mit einer berechneten Eigenschaft. Das ist eine kleine Hashtable (eine Liste aus Schlüssel und Wert in @{ }) mit zwei Einträgen: wie die neue Spalte heisst und wie PowerShell ihren Wert ausrechnet.

    

      
Get-ChildItem Logs | Select-Object Name, @{ Name = 'MB'; Expression = { [math]::Round($_.Length / 1MB, 2) } }

      
    
        
  • @{ … }: die Hashtable, sie steht wie ein Eigenschaftsname in der Liste nach Select-Object.
    • 
        
  • Name = 'MB': der Name der neuen Spalte. Statt Name darfst du Label schreiben.
    • 
        
  • Expression = { … }: die Rechnung, immer in geschweiften Klammern (ein Skriptblock).
    • 
        
  • $_: das Objekt, das gerade dran ist, hier eine Datei (wie bei Where-Object).
    • 
        
  • $_.Length / 1MB: Bytes geteilt durch 1'048'576 ergibt MB.
    • 
        
  • [math]::Round( … , 2): rundet auf zwei Nachkommastellen.
    • 
      

      

      
Die zwei kleinen Dateien haben weniger als 0.005 MB und werden zu 0.00. Die Schlüssel darfst du abkürzen, solange sie eindeutig sind: @{ n = 'MB'; e = { … } } wirkt gleich.

    

    

      
Select-Object oder Format-Table?

      
Berechnete Eigenschaften gehen bei beiden. Der Unterschied ist derselbe wie vorhin: Select-Object erzeugt echte Objekte mit der Eigenschaft MB. Du kannst danach sortieren, filtern und exportieren.

      
Get-ChildItem Logs | Select-Object Name, @{ n = 'MB'; e = { [math]::Round($_.Length / 1MB, 2) } } |
  Sort-Object MB -Descending | Select-Object -First 3

      

      
Format-Table zeigt die Spalte nur an. Dort heisst der Schlüssel meist Label, und es gibt Zusatzschlüssel wie Width (Breite) oder Alignment (Ausrichtung). Danach ist die Pipeline zu Ende.

      
Get-ChildItem Logs | Format-Table Name, @{ Label = 'MB'; Expression = { [math]::Round($_.Length / 1MB, 2) } }

    Lösungsfilm · Erst zuschauen, dann testen
    
Zwei Berichte für Wolkenried

    
Lea hat zwei Aufträge. (a) Das Personalamt will die Informatik mit Name, Vorname und Pensum als Datei Berichte\informatik.csv, mit Semikolon für Excel. (b) Der Leiter Informatik will alle Logdateien über 1 MB mit ihrer Grösse in MB, die grösste zuerst, als JSON-Datei Berichte\speicher.json für sein Überwachungsprogramm.

    
Jede Szene zeigt einen Befehl und die Ausgabe des Simulators auf Leas Rechner.

    

    

      Lösung zum Nachlesen
      

        
(a)

        
Import-Csv Berichte\mitarbeitende.csv | Where-Object Abteilung -eq Informatik |
  Select-Object Name, Vorname, Pensum | Export-Csv Berichte\informatik.csv -Delimiter ';'

        
Die Datei hat eine Kopfzeile und drei Zeilen: Keller (80), Meier (100), Bühler (100).

        
(b)

        
Get-ChildItem Logs | Where-Object Length -gt 1MB |
  Select-Object Name, @{ Name = 'MB'; Expression = { [math]::Round($_.Length / 1MB, 2) } } |
  Sort-Object MB -Descending | ConvertTo-Json | Out-File Berichte\speicher.json

        
Fünf Einträge: app-2026-07.log (8.5), app-2026-08.log (6.0), app-2026-09.log (4.5), app-2026-10.log (3.25), backup-2026-06.log (1.1).

        
Eigene Lösung, nicht vom Dozenten bestätigt. Alle Befehle in PowerShell 7.6 in einem nachgebauten Ordner geprüft.

      

    

  


  
  

    Typische Fehler
    
Die häufigsten Stolpersteine

    
Format-Cmdlet in der Mitte: Format-Table | Export-Csv, Format-Table | Where-Object oder Format-List | ConvertTo-Json arbeiten mit Formatierungsobjekten statt mit deinen Daten. Ergebnis: Unsinn in der Datei oder gar nichts. Für die Auswahl von Spalten nimmst du Select-Object, formatiert wird ganz am Schluss.

    
Komma-CSV in Schweizer Excel: Ohne -Delimiter ';' öffnet Excel die Datei oft so, dass alles in Spalte A steht. Beim Einlesen einer Semikolon-Datei brauchst du ebenfalls Import-Csv … -Delimiter ';', sonst wird die ganze Zeile zu einer einzigen Eigenschaft.

    
Zahlen aus CSV sind Text: Where-Object Pensum -lt 70 findet nach Import-Csv auch Pensen von 100, und Pensum + 20 ergibt 8020. Wandle vorher um: [int]$_.Pensum.

    
JSON zu flach: Siehst du die Warnung Resulting JSON is truncated oder Werte wie @{Ort=Wolkenried} im JSON, reicht die Standardtiefe 2 nicht. Erhöhe sie mit -Depth. In 5.1 fehlt die Warnung, prüfe das Ergebnis dort selbst.

    
Expression ohne geschweifte Klammern: Schreibst du Expression = $_.Length / 1MB, rechnet PowerShell sofort, bevor es überhaupt eine Datei gibt. Die Rechnung ergibt 0, und PowerShell meldet:
      
PS C:\Users\lea> Get-ChildItem Logs | Select-Object Name, @{ Name = 'MB'; Expression = $_.Length / 1MB }
Select-Object: The "Expression" key has a type, System.Int32, that is not valid; expected types are {System.String, System.Management.Automation.ScriptBlock}.

      Auf Deutsch: «Der Wert bei Expression ist eine Zahl. Erlaubt sind nur ein Text (Name einer Eigenschaft) oder ein Skriptblock.» Die Rechnung gehört in { }.

    
Out-File statt Export-Csv: Out-File speichert den Bildschirmtext. Import-Csv kann daraus keine sauberen Objekte machen. Für Daten, die ein Programm weiterverarbeiten soll, nimm Export-Csv oder JSON.

    
Umlaute in 5.1: Windows PowerShell 5.1 schreibt mit Export-Csv ohne -Encoding ASCII. Aus Bühler wird B?hler, für immer. Schreib dort -Encoding UTF8 dazu.

Unterschiede zu Windows PowerShell 5.1

      
    
        
  • Export-Csv und ConvertTo-Csv schreiben in 5.1 ohne -NoTypeInformation eine Zeile #TYPE …. In 7 fehlt sie; mit -IncludeTypeInformation holst du sie zurück.
    • 
        
  • Standard-Encoding von Export-Csv: 5.1 ASCII (Umlaute werden zu ?), 7 UTF-8 ohne BOM. Out-File schreibt in 5.1 UTF-16 LE.
    • 
        
  • ConvertTo-Json warnt erst ab PowerShell 7.1, wenn die Tiefe nicht reicht. 5.1 kürzt still, rückt anders ein und schreibt Datumswerte als \/Date(…)\/.
    • 
        
  • -UseQuotes und -QuoteFields (Anführungszeichen steuern) gibt es erst ab 7.0.
    • 
        
  • Ein Format-Cmdlet in der Mitte führt in 5.1 öfter zu einer Fehlermeldung (zum Beispiel Format-Table | Sort-Object), in 7 läuft derselbe Befehl ohne Meldung und ohne Wirkung.
    • 
        
  • Out-GridView läuft in beiden Versionen nur unter Windows mit Bedienoberfläche (nicht auf Windows Server Core). pwsh 7 auf macOS und Linux kennt es nicht.
    •
